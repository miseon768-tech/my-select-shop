# 챕터1-5 : Mockito란 무엇일까?

Service 단위 테스트 작성 시 의존 객체(Repository 등) 분리를 위한 Mock 객체 활용 방법 정리.

---

## 문제 상황

- `ProductService` 단독 테스트 시 생성자에 `ProductRepository`, `FolderRepository`, `ProductFolderRepository` 주입 필요
- 해당 객체들은 인터페이스 → 직접 생성 불가
- 내부의 `productRepository.findById()` 등 DB 호출 처리 불가

---

## Mock 객체란

- 실제 객체와 동일한 클래스명·메서드명을 가지나 실제 DB 작업은 수행하지 않는 가짜 객체
- 테스트에 필요한 결과값만 반환하도록 설정 가능
- 각 테스트 케이스를 서로 독립적으로 분리하기 위한 수단

---

## Mockito 사용법

- `@ExtendWith(MockitoExtension.class)` : `@Mock` 사용을 위한 클래스 레벨 설정
- `@Mock` : Mock 객체 선언 (Repository 등 의존 객체에 적용)
- `given(mock.method()).willReturn(value)` : Mock 객체의 메서드 호출 시 반환값 사전 정의 (사용 케이스 등록 필수)

---

## 주의사항

- `@Mock` 선언만으로는 부족 → `given()` 으로 사용 케이스를 정의하지 않으면 테스트 실패
- 최저가 미만 변경 테스트처럼 DB 조회가 필요 없는 케이스는 `given()` 없이도 테스트 가능
