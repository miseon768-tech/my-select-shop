# 챕터1-4 : 단위 테스트란 무엇일까?

버그 발견이 늦어질수록 비용이 기하급수적으로 증가하므로, 단위 테스트를 통한 사전 버그 발견 및 비용 절감 목적.

---

## 단위 테스트란

- 프로그램을 작은 단위로 쪼개 각 단위의 정확한 동작 여부를 검사하는 테스트 기법
- 빠른 작성 및 문제 위치 파악 가능

## 개발 단계별 테스트 시점

| 단계 | 설명 |
|---|---|
| Development | 개발 단계 |
| Unit Test | 개발자가 직접 수행하는 단위 테스트 |
| QA Testing | QA 팀이 Stage 환경에서 수행하는 블랙박스 테스트 |
| Production | 실 서비스 운영 환경 |

---

## JUnit5 주요 어노테이션

### 실행 순서 제어
- `@BeforeEach` : 각 테스트 실행 전 수행
- `@AfterEach` : 각 테스트 실행 후 수행
- `@BeforeAll` : 모든 테스트 시작 전 최초 1회 수행 (static 메서드)
- `@AfterAll` : 모든 테스트 종료 후 마지막 1회 수행 (static 메서드)

### 테스트 구성
- `@DisplayName` : 테스트 이름 지정
- `@Nested` : 주제별 테스트 그룹화
- `@Order` + `@TestMethodOrder` : 테스트 실행 순서 지정

### 테스트 반복
- `@RepeatedTest` : 지정 횟수만큼 테스트 반복, `RepetitionInfo`로 현재/총 횟수 확인
- `@ParameterizedTest` + `@ValueSource` : 여러 파라미터 값으로 반복 테스트

---

## Assertions 주요 메서드

| 메서드 | 설명 |
|---|---|
| `assertEquals(expected, actual)` | 예상값과 실제값 일치 여부 확인 |
| `assertNotEquals(expected, actual)` | 예상값과 실제값 불일치 여부 확인 |
| `assertTrue / assertFalse` | boolean 값 참/거짓 확인 |
| `assertNotNull / assertNull` | null 여부 확인 |
| `assertThrows(exceptionType, executable)` | 예상 예외 발생 여부 확인 |

---

## Given - When - Then 패턴

- **Given** : 테스트에 필요한 값(상태) 사전 선언
- **When** : 테스트 대상 실행
- **Then** : 예상 결과와 실제 결과 비교 검증
