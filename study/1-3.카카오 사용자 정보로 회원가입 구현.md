# 챕터1-3 : 카카오 사용자 정보로 회원가입 구현

카카오에서 받은 사용자 정보를 기반으로 신규 회원가입 또는 기존 회원 연동 처리 흐름 정리.

---

## 테이블 설계 결정

카카오 사용자를 위한 별도 테이블 생성 대신, 기존 User 테이블에 `kakaoId` 컬럼 추가 방식 채택.

| 방식 | 장점 | 단점 |
|---|---|---|
| 별도 테이블 (KakaoUser) | 결합도 낮음, 독립적 확장 가능 | 구현 복잡도 높음 |
| 기존 테이블 확장 | 구현 단순 | 결합도 높음 |

→ **기존 User 테이블 확장 방식 채택**. password는 UUID로 설정하여 폼 로그인 방지.

---

## 회원가입 처리 흐름

- **kakaoId 중복 확인** : DB에서 동일 kakaoId 보유 회원 존재 여부 확인
- **kakaoId 미존재 시** : 동일 email 보유 회원 추가 확인
    - 동일 email 존재 시 → 기존 회원에 kakaoId 업데이트
    - 동일 email 미존재 시 → 신규 회원가입 (password: UUID, email: 카카오 email)
- **처리 완료 후** : JWT 발급

---

## 주요 파일

| 파일 | 역할 |
|---|---|
| `KakaoService` | 회원 존재 여부 확인 및 신규 가입 / kakaoId 업데이트 처리 |
| `User` | kakaoId 컬럼 추가 및 kakaoIdUpdate 메서드 포함 |
| `UserRepository` | kakaoId, email 기반 회원 조회 메서드 추가 |
